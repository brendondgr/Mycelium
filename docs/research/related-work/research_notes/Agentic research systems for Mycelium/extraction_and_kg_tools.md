Scope note: researched 2026-11-08. Items marked **unverified** could not be confirmed.

Mycelium baseline being compared (from the assignment, not re-checked): LLM facet extraction (methods/datasets/tasks) from lab members' own papers into a Postgres KG (Concept, Edge, entity linker merging mentions into concepts, coauthorship edges; no Neo4j); synthetic eval recall 0.658→0.775, zero wrong merges; schema + deterministic grounding + one bounded repair for project-state extraction; typed Observations from lab chat; deterministic grant-eligibility rule engine; ingestion mostly titles/abstracts/metadata (full-text parsing likely a gap); fixed pipelines, no agent loop; CPU-only host, fastembed bge-small, OpenAI-compatible LLM endpoint.

## Q1. Which tools exist, with paper / venue / track / repo / licence / maintenance / CPU feasibility?

### Takeaway
The demo-track papers most directly comparable to Mycelium's language → KG layer are **PaperMage (EMNLP 2023 demo)**, **DeepKE (EMNLP 2022 demo)** and **OneKE (WWW 2025 demo)**; everything in the LLM-KG space (GraphRAG, LightRAG, HippoRAG, KGGen, iText2KG, AutoSchemaKG) is a main-track/Findings/arXiv paper, not a demo, and none targets scholarly facet graphs. On a CPU-only host the realistic parsers are **GROBID (CRF mode)**, **Docling** and **Marker (fast/no-OCR mode)**; olmOCR, Nougat and the MinerU VLM backend need a GPU.

### Inferences
- The language → KG layer's nearest prior art in demo tracks is DeepKE (toolkit, EMNLP'22), PaperMage (document substrate, EMNLP'23) and OneKE (agentic schema-guided extraction, WWW'25). None of them combines **personalised lab-scoped facet graphs + project-state + grounded repair + updates**, which is the gap Mycelium can claim.
- Licence hazards: Marker weights (revenue-gated), Nougat weights (NC), MinerU (non-standard), kg-gen (no licence), CERMINE (AGPL). Clean Apache/MIT options: GROBID, Docling, PaperMage, GLiNER (check model card), DyGIE++, iText2KG, LightRAG, HippoRAG, GraphRAG.
- CPU-only feasibility ranking for full-text ingestion: GROBID-CRF (proven at scale on CPU) > Docling (designed for commodity hardware) > Marker no-OCR (fast but low quality per its own table) >> olmOCR/Nougat/MinerU-VLM (GPU).

## Q2. What does each extract, how (rules / ML / LLM), with what schema, entity linking/merging, grounding/provenance and evaluation numbers?

### Takeaway
Two families: (1) supervised span-based scientific IE (SciERC→DyGIE++/PURE→SciER) with fixed Task/Method/Dataset(/Metric) schemas, character-span provenance, and modest F1; (2) LLM KG builders that differ mainly in **how they merge duplicates** (KGGen iterative clustering, iText2KG incremental matching, Neo4j builder similarity thresholds, AutoSchemaKG induced schema) and **how they retrieve** (GraphRAG communities, LightRAG dual-level, HippoRAG PPR, Graphiti bi-temporal). Only parsers (GROBID/PaperMage) carry true layout-coordinate provenance.

### Cited Findings
- GROBID: 68 labels per full run; header, references (DOI/PMID via biblio-glutton/CrossRef), citation contexts, sections, figures/tables, funders, data-availability statements, **PDF bounding-box coordinates**; reference extraction F1 ≈0.87 (PMC, 1,943 PDFs) / ≈0.90 (bioRxiv, 2,000 PDFs); citation-context resolution 0.76–0.91; reference parsing >0.90 instance / 0.95 field; ML over pdfalto layout tokens (CRF default, DeLFT optional) — [GitHub](https://github.com/grobidOrg/grobid).
- PaperMage: unified Python representation combining existing NLP and CV models with ready-made pipelines for scientific PDFs — [ACL Anthology](https://aclanthology.org/2023.emnlp-demo.45).
- Docling: layout (DocLayNet) + TableFormer models, unified document representation → Markdown/JSON — [arXiv](https://arxiv.org/abs/2501.17887).
- SciER: Dataset/Method/Task + 9 relation types over full text; NER, end-to-end RE, RE with gold entities; LLM baselines use few-shot ICL — [ACL Anthology](https://aclanthology.org/2024.emnlp-main.726). (Exact F1 numbers not retrieved — see gaps.)
- SciDMT: D/M/T mention spans, weak labels linkable to PwC + ontology linking for tasks/datasets; SciBERT and GPT-3.5 struggle — [NSF PAR](https://par.nsf.gov/biblio/10544555-scidmt-large-scale-corpus-detecting-scientific-mentions).
- DMDD: dataset-mention detection **and linking** baselines — [ACL Anthology](https://aclanthology.org/2023.tacl-1.64).
- CS-KG: automatic IE pipeline producing task/method/material/metric entities and 179 relation types, evaluated against manually annotated statements, periodically refreshed — [ORO](https://oro.open.ac.uk/85306).
- OneKE: schema agent picks/derives schema; extraction agent; **reflection agent uses a case repository of past errors to self-correct** — [arXiv](https://arxiv.org/abs/2412.20005v2).
- KGGen: S-P-O triples + iterative LLM clustering for entity & edge dedup; evaluated on MINE — [arXiv](https://arxiv.org/html/2502.09956v2).
- iText2KG: incremental entity then relation extraction, Graph Integrator resolves against existing graph, zero-shot, no post-processing — [arXiv](https://arxiv.org/pdf/2409.03284).
- AutoSchemaKG: schema-free triple + event extraction with conceptualisation; ~95% alignment with human schemas (self-reported) — [arXiv](https://arxiv.org/html/2505.23628v1).
- Neo4j builder dedup = embedding/text-distance thresholds + cleanup LLM; answers carry source metadata — [GitHub](https://github.com/neo4j-labs/llm-graph-builder).
- GraphRAG: entity KG + community summaries → map-reduce global answers — [arXiv](https://arxiv.org/abs/2404.16130). LightRAG: entity/relation-level + theme-level keys — [ACL Anthology preview](https://preview.aclanthology.org/new-sigs/2025.findings-emnlp.568/). HippoRAG 2: PPR seeded from query-matched nodes, passage nodes integrated — [arXiv](https://arxiv.org/abs/2502.14802v2). Zep/Graphiti: bi-temporal validity intervals on facts — [arXiv](https://arxiv.org/html/2501.13956).
- ReLiK: retriever proposes candidate KB entities/relations, reader aligns them to spans in one pass (closed IE with linking) — [arXiv](https://arxiv.org/abs/2408.00103).
- GLiNER: arbitrary label set given at inference, span–label matching with a small encoder — [PyPI](https://pypi.org/project/GLiNER/).
- Text2KGBench metrics include ontology conformance and hallucination rate — [arXiv](https://arxiv.org/abs/2308.02357).

### Inferences
- Mycelium's "deterministic grounding + one bounded repair" is the same pattern as OneKE's reflection agent, but OneKE adds a **case repository** of past failures used as retrieval context — a cheap upgrade.
- Mycelium's entity linker (mention → Concept merge, zero wrong merges) is directly comparable to KGGen clustering and iText2KG's integrator; MINE and SciER/SciDMT could replace or supplement the synthetic eval.

### Gaps
- SciER, SciDMT, DMDD headline F1 numbers not retrieved (need the PDFs).
- No published precision of LLM entity-merging (KGGen/iText2KG) on scientific method/dataset names specifically.

## Q3. How do these differ from Mycelium's facet / graph / state extraction?

### Takeaway
Mycelium is narrower in schema but deeper in **who** the graph is about: a per-lab, per-person graph (own papers, coauthorship, project state, chat observations) with deterministic checks, versus corpus-scale generic graphs (CS-KG, S2AG, GraphRAG-style) or document-scale parsers. Its main technical gaps relative to the field are full-text input, an external canonical ID space for concepts, a real benchmark, and graph-native retrieval.

### Cited Findings
- Scientific IE datasets restrict annotation to abstracts and lose body-text mentions; SciER annotates full text for this reason — [ACL Anthology](https://aclanthology.org/2024.emnlp-main.726). Mycelium ingests mostly titles/abstracts (assignment context) — so its facet recall is capped by input, not only by the extractor.
- CS-KG / SemOpenAlex / S2AG are global scholarly graphs with stable IDs, SPARQL/APIs and billions of triples — [ORO](https://oro.open.ac.uk/85306); [arXiv SemOpenAlex](https://arxiv.org/abs/2308.03671v1); [arXiv S2](https://arxiv.org/abs/2301.10140). Mycelium's Concept table has no external identifiers (assignment context).
- Graph-RAG systems (GraphRAG, LightRAG, HippoRAG) target QA over a corpus, not lab updates, and build generic untyped entity graphs — [arXiv GraphRAG](https://arxiv.org/abs/2404.16130); [LightRAG](https://preview.aclanthology.org/new-sigs/2025.findings-emnlp.568/).
- Neo4j builder requires Neo4j+APOC — [GitHub](https://github.com/neo4j-labs/llm-graph-builder); Mycelium deliberately stays on Postgres.
- Graphiti's temporal model (validity intervals, episodes) — [arXiv](https://arxiv.org/html/2501.13956) — is the closest analogue to Mycelium's project-state slow/fast split and ambient Observations; generic KG builders have no notion of time or consent.
- OneKE is agentic (schema/extraction/reflection agents) — [arXiv](https://arxiv.org/abs/2412.20005v2); Mycelium is fixed pipelines.

### Inferences
- Positioning: "typed, grounded, temporal, lab-scoped KG maintained from heterogeneous lab language (papers, project docs, chat) on a CPU box" is distinct from every catalogued system; none of the demo-track neighbours handles project state or consented chat.
- The weakest comparative point is evaluation: a synthetic set vs. community benchmarks (SciER, SciDMT, Text2KGBench, MINE).

### Gaps
- No catalogued system reports grounding-check pass rates comparable to Mycelium's deterministic checks; a head-to-head would need new measurement.

## Q4. What could Mycelium concretely adopt?

### Takeaway
Highest-value, CPU-compatible adoptions: (1) **GROBID (CRF) or Docling** for full-text of lab members' own papers to feed facets; (2) **SciER + SciDMT/DMDD** as the evaluation for facet extraction and linking; (3) **GLiNER-small** as a cheap first-pass D/M/T tagger before the LLM; (4) **OpenAlex Topics / S2 IDs / PwC-archive task-dataset IDs** as external anchors for Concept linking; (5) **HippoRAG-style PPR or LightRAG dual-level retrieval implemented in Postgres** as an agent tool; (6) OneKE's reflection + case repository and Graphiti's bi-temporal edges as patterns.

### Cited Findings and concrete proposals
- **Full-text parsing dependency** — GROBID runs CPU-only at ~10.6 PDFs/s on 16 cores with a Docker image, emits sections, citation contexts and coordinates — [GitHub](https://github.com/grobidOrg/grobid). Docling (MIT) is the alternative when Office/HTML docs (project documents) also need conversion — [arXiv](https://arxiv.org/abs/2501.17887). Avoid Marker weights / Nougat / MinerU for licence or GPU reasons — [Marker](https://github.com/datalab-to/marker); [Nougat PyPI](https://pypi.org/project/nougat-ocr/0.1.11); [olmOCR](https://github.com/allenai/olmocr).
  - Agent tool idea: `parse_paper(pdf) → sections + citation contexts`, so the agent can fetch a methods section on demand rather than pre-parsing everything.
- **Benchmark to replace/augment the synthetic eval** — SciER (full-text, exactly Dataset/Method/Task, OOD split) for extraction — [ACL Anthology](https://aclanthology.org/2024.emnlp-main.726); SciDMT (100 hand-annotated papers, PwC-linkable mentions) and DMDD (450 annotated articles, detection + linking) for mention→concept linking — [NSF PAR](https://par.nsf.gov/biblio/10544555-scidmt-large-scale-corpus-detecting-scientific-mentions); [ACL Anthology](https://aclanthology.org/2023.tacl-1.64); MINE for whole-graph quality — [arXiv](https://arxiv.org/html/2502.09956v2); Text2KGBench for schema conformance/hallucination metrics — [arXiv](https://arxiv.org/abs/2308.02357). Per CLAUDE.md these runs must be recorded under `docs/research/experiments/`.
- **Cheap first-pass NER** — GLiNER small checkpoint with labels {method, dataset, task} as a candidate generator / recall booster ahead of the LLM — [PyPI](https://pypi.org/project/GLiNER/); [ACL Anthology](https://preview.aclanthology.org/setup/2024.naacl-long.300). ReLiK as an alternative for linking-in-one-pass if a KB (e.g. PwC archive) is loaded — [arXiv](https://arxiv.org/abs/2408.00103).
- **External ontology linking** — OpenAlex Topics (4,516 topics, stable T-ids; Concepts frozen, don't build on them) — [OpenAlex](https://developers.openalex.org/guides/deprecations); PwC archive task/dataset/method tables on HF (static since July 2025) — [hyper.ai](https://hyper.ai/en/news/42900); CS-KG (CC BY 4.0) for method/task entities in CS — [ORO](https://oro.open.ac.uk/85306); S2AG paper/author IDs — [arXiv](https://arxiv.org/abs/2301.10140); SemOpenAlex (CC0) for RDF/SPARQL alignment — [arXiv](https://arxiv.org/abs/2308.03671v1).
- **Graph-RAG over the Postgres graph** — HippoRAG 2's PPR over a KG gave +7.7 pts on associativity tasks — [PMLR](https://proceedings.mlr.press/v267/gutierrez25a.html); LightRAG's dual-level keys — [ACL Anthology preview](https://preview.aclanthology.org/new-sigs/2025.findings-emnlp.568/); GraphRAG community summaries for "what's happening across the lab" global questions — [arXiv](https://arxiv.org/abs/2404.16130). All three are MIT and LLM-endpoint agnostic, but they bring their own storage; port the algorithm (PPR via recursive SQL or networkx on a lab-sized subgraph) rather than the dependency.
  - Agent tools: `graph_neighbors(concept)`, `related_work_via_ppr(seed_concepts)`, `lab_community_summary(cluster)`.
- **Patterns** — OneKE reflection agent + case repository of past extraction errors as few-shot repair context — [arXiv](https://arxiv.org/abs/2412.20005v2); KGGen iterative clustering for concept merging, as a comparison arm against the current linker — [arXiv](https://arxiv.org/html/2502.09956v2); iText2KG incremental integration against the existing graph — [arXiv](https://arxiv.org/pdf/2409.03284); Graphiti bi-temporal edge validity for project-state claims and Observations ("blocker true from t1 to t2") — [arXiv](https://arxiv.org/html/2501.13956); AutoSchemaKG schema induction to propose new facet types beyond D/M/T — [arXiv](https://arxiv.org/html/2505.23628v1).
- **Fine-tuning data** — SciRIFF's 54-task IE-heavy instruction set if Mycelium ever fine-tunes a small local extractor — [ACL Anthology](https://aclanthology.org/2025.emnlp-main.310).

### Inferences
- The most defensible NAACL-demo evaluation story: SciER test (+OOD) for facet extraction F1, SciDMT/DMDD for linking, plus Mycelium's grounding-check pass rate and repair yield — numbers no competing demo reports.
- Agentic transition: the parsers and graph-RAG algorithms above map naturally to tools; OneKE shows the demo community accepts a "schema agent + extraction agent + reflection agent" decomposition, which Mycelium's fixed pipeline already approximates.
- Biomedical tools (scispaCy, PubTator 3) are only worth it if Mycelium targets bio labs; PubTator's API could be a per-domain linker plug-in.

### Gaps
- No measurement of GROBID/Docling throughput on this specific CPU host; need a small experiment.
- Whether SciER/SciDMT licences permit redistribution inside an Apache-2.0 repo was not checked (SciER repo reports GPL-3.0 — likely keep it as an external download).
- GLiNER performance on scientific D/M/T labels specifically not found.
