# EXP-2026-09-017 — Results

## 1. Headline

Across 24 weeklies and 24 dailies for 21 sandbox people and 3 labs:
- every change reached exactly the reports it should (97 of 97 expected
  rows), and none reached a report it should not;
- every `[O#]` resolved;
- the interpretation line appeared exactly where H3 said;
- the dailies' "Changed today" matched the rule for every reader.

The registered run reported 11 violations. All 11 were the harness matching
topics by substring, and none was a routing error. The model-linking half of
H2 (`[P#][O#]`) was not exercised, because the sandbox people have no feed.

## 4. Interpretation

- **H1 (routing) — holds** once the harness matches rows by their structure.
  - Run 1's 8 "duplicated" hits were "annotation budget" found inside "the
    annotation budget came through".
  - Its 3 "leaked" hits were "Project C1 dataset", one person's personal told
    fact, found inside "Project C1 dataset arrival", another person's own.
  - Each row was checked by hand against the change table (ISSUES.md).
  - Covered in run 2 (97 rows):
    - personal changes to their owner only;
    - lab-visible changes on shared projects (A1, B2, C1) to the lab weekly
      and each member once;
    - lab-visible changes on unshared projects (A2, B1, C2) to their members
      only;
    - personal told facts on lab projects to their speaker only.
- **H2 (citations) — holds for resolution.** 97 `[O#]` cited and 0
  unresolved. No model sentence cited an `[O#]`, and the verifier removed none.
  That part of the weekly (why an item matters now) needs feed items in a
  project's packet, and none exist here. It is unmeasured: the unit tests show
  the verifier keeps a resolving `[P1][O1]` and removes an unresolved `[O9]`,
  but nothing shows how the model uses the change rows.
- **H3 (interpretation) — holds.** It appeared in no weekly with drift off.
  With drift on, it appeared in exactly the six weeklies of people with a
  confirmed, not-undone exploration this week.
- **H4 (dailies) — holds.** 24 dailies were generated and 0 mismatched. The
  line appeared for the Lab B members, from the accepted stated-state edit on
  shared B2, and for people with a profile edit in the last 24 hours. It
  appeared in the Lab B daily alone among labs. No lab daily had a
  development line.
- **H5 (budget) — holds.** Under 25 seconds per run.
- **Found and changed after run 1:** an undo of a change from the same week
  rendered as a second row beside the change's own "(since undone)". It is
  now a mark on that row only.

## 5. Threats to validity

- The routing is checked by the same membership and visibility rules the
  feature implements, restated independently in the harness. A shared
  misunderstanding of the rule would pass both. The rule itself is the plan's
  acceptance criteria, quoted in PROTOCOL.md.
- Planted rows: the shared flags, and one lab-visible told fact per project
  (listed in `run.py`). Every other change is real, from EXP-2026-09-015 and
  EXP-2026-09-016.
- There are no feed items, so the weeklies' model-written sections are
  fallback lines, and the overview is the only model call.

## 6. What surprised us

The only failures were in the checker, and they came from topic names that
nest inside each other ("Project C1 dataset" inside "Project C1 dataset
arrival"). A report reader would not have been misled. But any future check
that greps report text for a topic has the same trap.

## 7. Follow-ups

- Measure how the model uses `[O#]` on a sandbox with feed items: whether it
