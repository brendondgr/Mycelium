## 3. What the run exposed: the deployed feed is not reproducible run to run

Not caused by this change — **found with the flag off**, i.e. in the pipeline as
it stands today.

Fusing the same profile against the same store in separate processes produces a
**different surfaced order**: three runs agreed, a fourth did not. With
`PYTHONHASHSEED=0` every run agrees.

The cause is two lines in `apps/content/fusion.py`:

```python
all_ids: set[str] = set()          # combine_interests, and again in combine_clusters
...
for item_id in all_ids:            # <- iteration order of a set of str
```

Candidates are collected into a **set** and iterated in hash order. Python
randomizes string hashing per process, so ties in `combined_score` — which are
common, because the score is a mean of a handful of normalized values — are broken
by the process's hash seed. `combined.sort(...)` is stable, so it preserves
whatever arbitrary order the set produced.

This is exactly the trap `EXP-2026-08-003` ISSUES recorded for `combine_clusters`
in an experimental context, still live in the deployed path and affecting the
product rather than a measurement: **the same profile, the same corpus and the
same code can produce two different feeds, and "what is new" is computed from the
Top-25 of that order.**

The fix is one word in each of two loops — `for item_id in sorted(all_ids)` — but
it is a change to `fusion.py` that alters the feed for every existing target, so
it needs its own before/after run under the re-run rule and is **out of scope
here**. Recorded as `Q-035`.

Scope of the observation: two interests, one store, four processes. The mechanism
is certain (the hash-seed control is decisive); the *rate* is not measured.

## 4. What this changes

- The rerank stage is cleared to ship behind its flag: off is provably identical,
  on behaves as specified and records its own audit trail.
- **`Q-035` opened** — non-deterministic tie ordering in `combine_interests` and
  `combine_clusters`, present in production today.
- Nothing about whether reranking *helps*. That is still `Q-033`, still a
  preference, still unmeasured.
