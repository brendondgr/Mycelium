# EXP-2026-09-016 — Results

## 1. Headline

The registered run found three real defects and failed H1 and H3:
- the answer card left the list before Mylo's reply could be read;
- twelve serious colour-contrast failures;
- a first profile entry could not be undone (the undo was refused with a 400).

With fixes in between, run 4 passes every check (n=1 per run, one person, two
viewports). All five hypotheses hold there. The first three runs are not
passes.

## 4. Interpretation

- **H1 (flows) — failed as registered; holds at run 4.** Two of run 1's
  failures were defects in the feature:
  - The answer card showed Mylo's reply in its own state, but answering
    refetches the list and the answered question leaves it, taking the reply
    with it. A person who answers on the web never saw what Mylo would do. The
    reply now lives in a live region above the list.
  - Undoing someone's first learning goal restored `null`, which the interests
    contract refuses, so the undo returned 400. A field that did not exist
    before is now removed on undo, along with the edit's provenance row.

  No unit test undid a field that had not existed before; the browser found it
  because a real sandbox person had never set one. The lab overview's "What
  changed" card was missing because the sandbox lab had no profile. That was a
  gap in the data, fixed in prep, not in the feature.
- **H2 (keyboard) — holds at run 4.**
  - The tabs follow the arrow-key pattern, and Tab enters the panel.
  - Every control in the answer, change and settings panels is reachable.
  - Every button's focus is visible.
  - Runs 2 and 3's keyboard failures were harness errors: a live
    `getComputedStyle` compared with itself, and a date input's segments
    restarted by refocusing.
- **H3 (axe serious/critical) — failed as registered (12 pairs, all
  `color-contrast`); 0 from run 2.**
  - `--text-muted` (#7f8775) is 3.4–3.7:1 on the light surfaces and 3.0:1 on
    the chip; WCAG AA needs 4.5:1 for small text.
  - The shared tab bar's active label (#5e7a3e on its 7% tint) is 4.05:1.
  - Fixed within the feature by using `--text-secondary`, which passes. The
    tab bar's active label moved to `--brand-primary-hover`, a change to a
    shared primitive that improves every page using it.
  - `--text-muted` itself is used app-wide and still fails wherever it sets
    small text. That is outside this feature and is follow-up §7.
- **H4 (phone) — holds.** There is no horizontal page scroll on any page at
  390 px. All 13 answer buttons are at least 24×24.
- **H5 (clean) — holds at run 4.** Run 2's one console error was the refused
  undo's 400.
- **Named controls (no bar).** Run 1 had five buttons all named "Undo" and
  three each named "Edit" and "Delete". They are now "Undo: <topic>", "Edit
  <topic>" and so on. One name still repeats: "Undo: things I'm picking up"
  appears twice, for two changes with the same topic, the profile edit and
  the confirmed understanding.

## 5. Threats to validity

- One person, one browser engine (Chromium), light theme only. Dark theme
  contrast was not measured.
- axe-core finds only the machine-checkable part of WCAG. No screen reader was
  used, so live-region announcements are asserted by role, not heard.
- The data is partly planted (listed in `data/prep.json`). The flows it
  exercises are real API calls on real rows.
- Each run was preceded by a fresh copy of the database and the same prep, so
  runs differ only by code, except that run 2 onward also has the lab profile.

## 6. What surprised us

The data the browser used carried a bad correction from EXP-2026-09-015. The
reader had taken "things I'm picking up" (where to file the topic) as a new
name for "argument mining", and the applier wrote it into her profile as a
learning goal. The unit tests had covered each piece, but none of them
followed a real reply all the way to the page. Reader r5 now drops filing
words, and the prompt forbids them; that change is not yet measured (Q-049).

## 7. Follow-ups

- `--text-muted` fails WCAG AA for small text on the light surfaces across
  the app. This is a design-system decision (darken the token, or keep it for
  large text only).
- Measure dark-theme contrast for the ambient pages.
- Re-measure reader r5 on a fresh seed (already Q-049).
