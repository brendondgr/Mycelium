# EXP-2026-09-021 — Results

## 1. Headline

The same 1,270 messages, replayed through Discord, Slack's signed Events API
and the Teams Bot Framework endpoint with real RS256 tokens, left the same
ledger:
- run 1 (registered): the same 1,118 people's messages kept, with 0
  differences, and the same drops;
- run 2 (post hoc: a third of people opted out, a fifth on a free plan, a
  seventh of channel lines from people with no account): 531 kept, with 0
  differences, and every refusal counter equal.

The one difference is the predicted one: Teams keeps none of Mylo's own 23 DM
lines, because it never delivers a bot's own messages.

## 4. Interpretation

- **H1 and H2 hold, in both runs.** Past the adapter, a platform changes
  nothing:
  - the kept multiset (speaker, content hash) is identical;
  - every drop counter is identical: not opted in 339, free 102, no account
    146, too short 129 in run 2.

  This is the test Plan 11 set itself ("if a plan needs to change anything
  outside the adapters, the abstraction was wrong"). Two things did change
  outside them, both as additions:
  - a transcript-only filter in the reading step (steps 9–10);
  - the `askable` check, which now accepts a Slack or Teams identity.

  Neither changes what an existing platform does.
- **H3 holds and matters.** On Teams the personal-chat window lacks Mylo's
  questions. The dialogue still works: an answer is read against the open
  question, not the window. But Plan 04's reading of a Teams DM sees answers
  without the question that prompted them. EXP-2026-09-013 treats a reply to
  Mylo as engagement rather than independent interest; on Teams that link is
  only as good as the reply-to id. The fix, if it proves to matter, is to
  record Mylo's own outgoing Teams lines at send time from the outbox.
- **H4 holds.** Every request passed its real endpoint, with its signature
  or token verified, and returned 200.
- **H5 holds.** 3.5 minutes for run 1 and 2.5 for run 2.

## 5. Threats to validity

- The mirror is ideal: every Discord identity has a matching Slack or Teams
  one. Real labs will link unevenly, and that changes who is heard on each
  platform. That is a coverage question, not a parity one.
- The events are built by the harness in each platform's documented shape.
  Real payloads carry more fields and subtypes. Threads, file shares and
  edited messages are covered by the unit tests, not here.
- Run 2 was added after run 1's results were seen, because run 1 exercised
  only the too-short drop. It is labelled post hoc. Its mix is deterministic
  (index modulo), fixed in the harness code.

## 6. What surprised us

Nothing in the gate needed to know which platform a message came from, not
even the refusals. The one real difference is structural, not a bug: Teams
will not tell a bot what it said.

## 7. Follow-ups

- Record Mylo's outgoing Teams lines at send time if Teams DM windows prove
  to need them (see §4).
- Run the same parity check with real payload captures from a test Slack
  workspace and Teams tenant before either is turned on.
